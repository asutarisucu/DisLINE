# DisLINE

自分のLINEアカウントをDiscordサーバーに橋渡しし、LINEのやり取りをDiscord上で完結させるBotです。
LINEのトークがDiscordのチャンネルとして展開され、そのチャンネルで発言するとLINEに送信されます。

現在は**自分専用（1インスタンス＝1LINEアカウント）**の構成です。

## 動作要件

- 自分が管理するDiscordサーバー（このBot専用のサーバーを作ることを推奨）
- 実行環境はどちらか
  - **Docker**（自宅サーバーで常時稼働させる場合 → [自宅サーバーで動かす](#自宅サーバーで動かす)）
  - **Node.js 24 以上**（手元で動かす場合）

TypeScriptをNodeが直接実行し、SQLiteは `node:sqlite`（組み込み）を使うため、
どちらの経路でもビルドステップとネイティブモジュールのコンパイルはありません。

## セットアップ

必要な設定は **Discord の Bot トークン 1つだけ**です。アプリID・サーバーID・あなたのユーザーIDは
起動時に自動で判別します。

### 1. Discord Bot を作る

1. [Discord Developer Portal](https://discord.com/developers/applications) で **New Application**
2. **Bot** タブ → Token を発行して控える
3. 同じ Bot タブで **MESSAGE CONTENT INTENT を有効にする**
   （これが無いとDiscord側の発言内容が空になり、LINEへ何も送れません）

招待URLはここでは要りません。起動するとログに出ます。

### 2. 起動する

自宅サーバーで常時稼働させる場合 → [自宅サーバーで動かす](#自宅サーバーで動かす)

手元で動かす場合:

```sh
npm install
cp .env.example .env      # DISCORD_TOKEN を書く
npm start
```

### 3. サーバーに招待する

起動するとログに招待URLが出ます。開いて、自分のサーバーを選んでください。

```
[discord] まだサーバーに参加していません。次のURLを開いて、このBotを自分のサーバーに招待してください。

  https://discord.com/api/oauth2/authorize?client_id=...&permissions=...&scope=bot%20applications.commands

招待されたら自動で続きを行います。
```

このURLには**このBotが実際に使う権限だけ**が入っています（コードから生成しているので、
権限の過不足が起きません）。招待するとスラッシュコマンドが自動で登録されます。

Bot専用のサーバーを作ることを推奨します。**チャンネルはそのサーバーのメンバー全員に見えます。**

### 4. LINEにログイン

Discordで `/line login` を実行すると、自分にだけ見えるQRコードが表示されます。
LINEアプリのQRリーダーで読み取り、表示された本人確認番号が一致することを確認してください。

続けて `/line setup` を実行すると、`LINE` カテゴリと `#dis-line-log` チャンネルが作られます。

> **複数のサーバーに招待した場合**、どれを使うか決められないため起動時に候補を表示して停止します。
> `.env` の `DISCORD_GUILD_ID` で指定してください。

## 使い方

**メッセージが届いたトークは自動でチャンネルになります。** 事前の登録は要りません。

同時に開けるのは `MAX_OPEN_CHANNELS`（既定 40）件までで、これを超えると
**最終活動が最も古いチャンネルから自動で閉じます**。閉じたことは `#dis-line-log` に記録され、
次にそのトークにメッセージが届けば同じ名前で開き直されます。
消したくないトークは、たまに発言するか `/line open` を打てば最後尾に回ります。

### メッセージの種類

| LINE | Discordでの見え方 |
|---|---|
| テキスト | そのまま（送信者の名前とアイコン付き） |
| 画像・動画・音声・ファイル | 添付ファイルとして再アップロード |
| スタンプ | 画像として表示（動くスタンプはAPNGのまま動きます） |
| 位置情報・連絡先など | 種別のラベルのみ |

`MAX_UPLOAD_MB`（既定 8）を超えるものは添付されず、種別とサイズが表示されます。

Discord から LINE へは、テキストと添付ファイルを送れます。
Discord のスタンプは LINE のスタンプIDに対応付けられないため送れません。

### 返信

LINE の返信は引用行としてDiscordに出ます。引用部分は元メッセージへのジャンプリンクです。
（Webhook はDiscordのネイティブな返信を使えないため、この形にしています）

Discord で**返信**して送ると、LINE 側でも返信として届きます。

### あなたの発言もWebhookで投稿し直されます

Discordで発言すると、LINEへ送ったあと、Botがそれを**Webhookで投稿し直して元のメッセージを消します**。
一瞬ちらつきますが、これには理由があります。

- Botが編集できるのは**自分がWebhookで投稿したメッセージだけ**です。あなたが投稿したままだと、
  送信を取り消したときに本文を差し替えられず、消すしかなくなります
- 副産物として、あなたの発言もLINEの表示名とアイコンで並び、チャンネル全体がLINEのトーク画面に近くなります

LINEへの送信が失敗した場合は投稿し直しません。元のメッセージは ❌ が付いた状態で残ります。

### 送信取り消し

- **LINE で取り消す** → Discord 側の本文が `🚫 送信が取り消されました` に置き換わります
- **Discord で取り消す** → メッセージを**右クリック（スマホは長押し）→ アプリ → 「LINEで取り消す」**
  LINE 側で取り消され、Discord 側も同じ位置で `🚫 送信が取り消されました` に置き換わります

どちらも削除ではなく差し替えなので、会話の並びが崩れず、何かが取り消されたことが残ります。

LINE側の取り消しに失敗した場合（**LINEの送信取り消しには時間制限があります**）、Discord側も変更しません。
片方だけ消えて食い違うことがないようにしてあります。

なお、メッセージを普通に**削除**した場合もLINE側で取り消されますが、
削除されたものは復元できないためDiscordからは完全に消えます。位置を残したいときは上の右クリックを使ってください。

### 既読

以下の2つのタイミングで、LINE側に既読が付きます。それ以外では付きません。

- **そのチャンネルで発言したとき** — 返信したなら読んでいる、という前提でトークの未読をまとめて既読にします
- **転送されたメッセージにDiscordでリアクションを付けたとき** — そのメッセージまでを既読にします

受信しただけでは既読は付かないので、寝ている間に届いたメッセージに勝手に既読が付くことはありません。

### コマンド

| コマンド | 説明 |
|---|---|
| `/line login` | QRコードでLINEにログイン |
| `/line logout` | ローカルのセッションを破棄 |
| `/line status` | ログイン状態と展開中のチャンネル一覧 |
| `/line setup` | カテゴリとログチャンネルを作成 |
| `/line list [query]` | グループ・友だちの一覧 |
| `/line open <chat>` | まだ届いていないトークを先に開く（名前で補完が効きます） |
| `/line close` | そのチャンネルを閉じる（トークは消えません。開き直せます） |
| `/line sync` | グループ・友だち一覧を取り直す |

## 動作確認手順

型チェックと単体テストは自動化されています。

```sh
npm run typecheck
npm test
```

実際の橋渡しは実アカウントが要るため、以下は手で確認してください。

1. `npm start` → コンソールに `としてログインしました` が出る
2. `/line login` → QRを読み取り、`✅ … としてログインしました` が返る
3. `/line setup` → `LINE` カテゴリと `#dis-line-log` ができる
4. 誰かにLINEでメッセージを送ってもらう → **チャンネルが自動でできて、送信者の名前とアイコンで表示される**
   （名前が `不明なユーザー (u19ad93b)` になる場合はコンソールの `[line] … 表示名を取得できませんでした` を確認）
5. そのチャンネルで発言 → LINE側に届く
6. **手順5の発言がDiscordに二重表示されないこと**（エコー抑止の確認）
   - 短いテキストを立て続けに何通か送って、どれも二重にならないことを確認する
   - コンソールに `送信応答にメッセージIDがありませんでした` が出ていないか確認する
7. **手順5の直後、相手のLINEに既読が付くこと**
8. 別のメッセージにDiscordでリアクションを付ける → **そこまでが既読になること**
9. **LINEアプリ本体から同じトークに発言** → Discord側にも表示されること
10. **画像・スタンプ・ファイルを送ってもらう** → 添付として表示されること（動くスタンプが動くこと）
11. **Discordから画像を添付して送信** → LINE側に画像として届くこと
12. **LINEで返信付きのメッセージを送ってもらう** → 引用行が出て、リンクが元メッセージに飛ぶこと
13. **Discordで返信して送信** → LINE側でも返信として表示されること
14. **LINEで送信取り消し** → Discord側の本文が `🚫 送信が取り消されました` に変わること
15. **Discordで発言** → 自分の発言もLINEの名前とアイコンで投稿し直されること（元のメッセージが消えること）
16. **その発言を右クリック → アプリ → 「LINEで取り消す」** → LINE側で消え、**Discordでは同じ位置が
    `🚫 送信が取り消されました` に変わること**（末尾に出るのではなく、その場で置き換わること）
17. `MAX_OPEN_CHANNELS=2` にして再起動し、3つ目のトークを受信 → **一番古いチャンネルが消え、`#dis-line-log` に記録が出ること**
18. Botを再起動 → `/line login` 無しで再開すること

## 自宅サーバーで動かす

Docker Compose で常時稼働させます。サーバー側に Node のインストールもビルド段も要りません。

### 初回

```sh
git clone <このリポジトリ> dis-line && cd dis-line
cp .env.example .env      # 値を埋める
docker compose up -d --build
docker compose logs dis-line          # 招待URLが出る
```

ログのURLを開いてサーバーに招待すると、スラッシュコマンドが自動で登録されます。
そのあと Discord で `/line login` → `/line setup`。

### すでに手元で動かしているセッションを引き継ぐ

`/line login` をやり直さずに移す場合、`data/` の中身をボリュームへ入れます。
**`-wal` ファイルにはまだ本体へ反映されていない更新が入っている**ので、必ずディレクトリごと移してください。

```sh
# 1. 手元で動いているインスタンスを止める（同じLINEセッションを2プロセスで使わない）
# 2. data/ をサーバーへ転送してから:
docker compose create
docker run --rm -v dis-line-data:/dst -v "$PWD/data:/src:ro" alpine   sh -c 'cp -a /src/. /dst/ && chown -R 1000:1000 /dst'
docker compose up -d
```

### 更新

```sh
git pull
docker compose up -d --build
```

**`--build` は必須です。** 省くと compose が古いイメージを使い回し、変更が反映されないまま
「起動しました」と表示されます。
スラッシュコマンドは定義が変わったときだけ自動で登録し直されるので、手動の作業はありません。

### 確認

```sh
docker compose ps                                   # STATUS が healthy になること
docker compose logs -f --tail 50
docker compose exec dis-line cat /app/data/health.json   # state: ok / waiting-login
```

### 止まったときに自動で復帰する仕組み

linejs のポーリングは、失敗しても**プロセスが生きたまま橋渡しだけ止まる**ことがあります。
この状態は再起動ポリシーでは救えない（終了していないため）ので、5分おきに LINE へ疎通確認し、
3回続けて失敗したら自分から終了します。`restart: unless-stopped` が起動し直し、
保存済みトークンで再開します。

ヘルスチェックは `data/health.json` の更新時刻を見ています。15分以上止まれば
`docker compose ps` の STATUS が unhealthy になります。

### データとバックアップ

`dis-line-data` ボリュームに **LINE の認証トークンと E2EE 鍵**が入っています。
失うと `/line login` からやり直しです。

```sh
# バックアップ
docker compose stop
docker run --rm -v dis-line-data:/src -v "$PWD:/out" alpine   tar czf /out/dis-line-backup-$(date +%F).tar.gz -C /src .
docker compose start

# 復元
docker compose stop
docker run --rm -v dis-line-data:/dst -v "$PWD:/in" alpine   sh -c 'rm -rf /dst/* && tar xzf /in/dis-line-backup-YYYY-MM-DD.tar.gz -C /dst && chown -R 1000:1000 /dst'
docker compose start
```

バインドマウント（`./data:/app/data`）にすればファイルを直接触れますが、
**SQLite は POSIX のファイルロックを要求する**ので、置き場所を選びます。

| 置き場所 | 可否 |
|---|---|
| 名前付きボリューム | ○ どの環境でも動く（既定） |
| Linux のローカルディスク（ext4等）へのバインドマウント | ○ 動く。`mkdir -p data` を先に |
| Docker Desktop（Windows/macOS）のバインドマウント | ✗ `disk I/O error` で起動できない |
| NFS / SMB / NAS 越し | ✗ 同上、またはデータベース破損 |

### ログ

`json-file` ドライバで 10MB × 5 世代に制限してあります。24時間動かし続けてもディスクを圧迫しません。
送信失敗時の診断ログに **LINE のメッセージ本文が出る経路がある**ため、ログの扱いは認証情報と同程度に。


## 制限と既知の事項

**運ばれないもの**

- **LINEのリアクション**は同期されません。Discordでリアクションを付けると既読が付くだけで、LINE側にリアクションは付きません
- **LINE絵文字（本文に埋め込まれるsticon）** は画像になりません。テキストの一部として置換前の文字のまま出ます
- **位置情報・連絡先・リッチメッセージ**などは種別ラベルのみで、中身は運ばれません
- **OpenChat（Square）** は対象外です（`listen({ square: false })`）

**Discordの制限**

- 1カテゴリ50チャンネル。超えると `LINE-2` を自動で作ります。ただしサーバー全体で500チャンネルが上限です。
  `MAX_OPEN_CHANNELS` はこれより十分小さい値にしてください。
- チャンネル名・トピックの変更は10分に2回まで。LINE側でトーク名が変わってもチャンネル名は自動追従しません（`/line close` で閉じれば、次の受信時に新しい名前で作り直されます）。
- 公式アカウントや広告も自動でチャンネル化されます。頻度が低ければ自動クローズで押し出されますが、
  うるさい場合はLINE側でブロックしてください。

**セキュリティ**

- `data/` には LINE の認証トークンとE2EE鍵が平文で入ります。`.gitignore` / `.dockerignore` 済みですが、**このディレクトリを共有・コミットしないでください。** イメージにも焼き込まれません。
- 送信失敗時の診断ログに **LINEのメッセージ本文が出る経路があります**（`bridge.ts` の警告）。ログの取り扱いは `data/` と同程度に。
- `/line logout` はローカルのセッションを消すだけです。LINE側の端末登録はLINEアプリの「ログイン中の端末」から削除してください。
- `npm audit` は間接依存の `thrift` に high 2件を報告します（Uncontrolled Recursion / Path Traversal 等）。これは thrift パッケージのHTTPサーバ・静的配信機能に対するもので本Botは使用していません。linejs が固定している依存のため、こちら側では解消できません。

**規約**

LINEJS は LINE の非公式クライアント実装です。自動化されたクライアントによるアクセスは LINE の利用規約に反し、**アカウントが利用停止になる可能性があります。**
また LINE 側の内部仕様変更で予告なく動作しなくなります。自己責任で利用してください。

## 構成

```
src/
  config.ts            環境変数
  store.ts             SQLite（トーク⇔チャンネル対応、送信済みID、メッセージ対応表）
  echo.ts              自分の送信がpollingで返ってきたときの抑止（ID照合の順序依存を補う）
  health.ts            疎通の見張り。復旧しなければ終了して再起動に任せる
  runtime.ts           起動時に確定する値（アプリID・対象サーバー・所有者）
  index.ts             エントリ。設定の自動判別とイベント配線
  bridge.ts            LINE→Discord / Discord→LINE の変換
  line/
    session.ts         QRログイン・トークン永続化・再開
    directory.ts       グループ/友だち一覧のキャッシュ
    media.ts           画像/スタンプ/ファイルの取得と種別判定
    util.ts            mid判定・chatId解決・表示名/アイコン
  discord/
    channels.ts        カテゴリ/チャンネル/Webhookの管理
    commands.ts        スラッシュコマンドと右クリックメニュー
    permissions.ts     必要な権限の定義と招待URLの生成
```
